# Development environment

Docker Compose setup with WordPress 7.1.3 (PHP 8.4), MariaDB 11.8.6 and Nextcloud 34.0.4
(Photos 7.0.0 bundled, Memories 10.2.0) over HTTPS with a generated development CA.

Requirements on the host: Docker with Compose v2, `bash`, `openssl`, `curl`.

```sh
dev/bin/setup.sh   # build, start and seed (idempotent; first run takes a few minutes)
dev/bin/reset.sh   # remove containers and volumes (all seed data)
```

| | URL | Login |
|---|---|---|
| WordPress | http://localhost:8080/wp-admin/ | `admin` / `WP_ADMIN_PASSWORD` in `dev/.env` |
| Nextcloud | https://localhost:8443/ | `admin` / `NC_ADMIN_PASSWORD` in `dev/.env` |

Inside the Compose network the plugin connects to `https://nextcloud.test` as `linker` with the
app password from `dev/.secrets/linker-app-password`.

All passwords, the CA and the certificates are generated on the first run
(`dev/.env`, `dev/.certs/`, `dev/.secrets/`) and are ignored by git. The host trusts nothing:
use `--cacert dev/.certs/ca.crt` for requests to `https://localhost:8443`.

## Seed data

Nextcloud accounts `content` (owner of the test files) and `linker` (connection account,
member of group `wpncl-editors`). Files are generated by `nextcloud/make-fixtures.php` and
uploaded via WebDAV.

| Where | Content | Purpose |
|---|---|---|
| `content:/Shared With Linker/` → shared with `linker`, read-only, download allowed | 2 JPEGs, 1 PDF, `Subfolder/` with a PNG | Folders, documents |
| `content:/Hidden Download/` → shared with `linker`, download **not** allowed | 1 JPEG | Download restriction (Abnahme 9) |
| Album `Shared Album` of `content`, shared with `linker` | 2 JPEGs + `large-original.jpg` (~70 MB) | Shared albums, streaming (Abnahme 5) |
| Album `Group Album` of `content`, shared with group `wpncl-editors` | 1 PNG | Group-shared albums |
| Album `Linker Album` of `linker` | 1 JPEG (`linker:/Own/`) | Own albums |

WordPress users: `admin`, `editor`, `author` (has `upload_files`), `subscriber`
(password `WP_USER_PASSWORD`).

## Properties mirrored from the target installation

- `DISALLOW_FILE_MODS`, `WP_DEBUG` on; PHP messages go to `docker compose logs wordpress`.
- Direct requests to `*.php` below `wp-content/` are denied by Apache.
- `open_basedir` for web requests, `memory_limit = 256M`.
- The plugin is mounted read-only; `dev/` itself is never served.

## Development-only adjustments

- `wordpress/mu-plugins/wpncl-dev.php` points the plugin's CA bundle (filter `wpncl_ca_bundle`)
  to the system store, which contains the development CA. TLS verification stays on.
- The containers have no internet access: `WP_HTTP_BLOCK_EXTERNAL` (only `nextcloud.test`
  allowed) and `wordpress/mu-plugins/wpncl-dev-offline.php` disable the wordpress.org update
  checks and language list, which would otherwise log PHP warnings. WordPress runs in `en_US`;
  the plugin's own `de_DE` translation does not depend on core language packs being installed.
